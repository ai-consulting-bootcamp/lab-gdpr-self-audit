# Data Processing Brief: Fix My Process

**For:** Data Protection Officer · **From:** Ayhan Demir · **Date:** 17 Nov 2026
**System:** Fix My Process, an internal assistant prototype for Kleinanzeigen (Ironhack Project 3). Employees describe a slow or manual work task; the system researches it, checks it against four internal AI documents (fictional in the prototype) and returns a fix report. The AI enablement team receives a use-case summary for every case.

## 1. What personal data does the system process?

No name, email or login is collected. The personal data comes from what employees write and from what the system records about each case:

| Data | Detail |
|---|---|
| **Problem description** (free text) | Can contain names of colleagues or customers, pasted customer details and the employee's views on their work. Only an on-screen warning asks people to leave names out. |
| **Department, current tools, frequency** | Chosen or typed by the employee. In a small department, department plus problem text can identify one person. |
| **Chat messages** | Up to the last 10 messages of a chat session, keyed by a random session ID that is not stored in the case record. |
| **Feedback** | Yes/No on "Will you use the suggested tool?" plus a free-text reason: data on the employee's attitude to tools. |
| **Inferred data** | Compliance flag (green / amber / red) on the described use, recommended tools, "no internal solution" flag, effort and impact ratings, confidence score, and two generated reports that can repeat anything in the description. |
| **Case metadata** | Reference code, timestamps, entry channel (web form, web chat, backup form or chat), run duration. |
| **Board decision** | "Added to pipeline" / "Dismissed" and time. Slack itself records which Board member clicked. |
| **Error records** | Failed step, time and the first 300 characters of the error message, which can contain input fragments. |
| **Technical data** | IP addresses and request metadata in the hosting and workflow logs. |

## 2. Where does the data come from?

From **employees directly** (web form or chat, feedback box), **generated by the AI model** (reports, flags, ratings), **Board members** (Slack review buttons), **public third-party sources** (web pages, news, research-paper metadata without author names) and **internal documents** uploaded by the AI enablement team. No HR or customer database is connected.

## 3. What is the data used for?

(1) Writing the employee's fix report. (2) Flagging whether the described use is allowed under the internal AI policy. (3) Creating a use-case summary for the AI enablement team. (4) Sending red cases to the AI Governance Board. (5) Status lookup by reference code. (6) Collecting feedback on tool adoption. (7) Scoring report quality. (8) Keeping chat context within one session. (9) Detecting and fixing workflow errors.

## 4. Who processes it, and where?

| Service | Role | What it receives | Location |
|---|---|---|---|
| n8n (instance hosted by Ironhack) | Runs every step | All data; keeps execution history by default | Not documented |
| OpenAI | AI model (research, reports, quality check) and search embeddings | Problem text, department, tools, frequency, chat history, search results | US |
| Cohere | Ranks search results | Problem text as the ranking query, internal document passages | Canadian company, infrastructure on Google Cloud, US |
| Pinecone | Document search | Numeric embeddings of search queries; internal document passages | AWS us-east-1, US |
| Tavily | Web search | Search query the AI writes from the problem | US |
| GNews | News search | 2 to 4 word topic query | Not documented |
| OpenAlex | Research-paper search | Keyword query | US |
| Airtable | Case database | Full case record (35 fields) and error records | US |
| Notion | Use-case summaries | One page per case, including the problem text | US |
| Slack | Board notices, red-case review, error alerts | Department, summary; full problem text for red cases | US |
| Render | Hosts the web page | Form and chat data in transit, request logs | Region not recorded in the project documentation; Frankfurt is Render's only EU region |

All services run on free or trial plans. No data processing agreements are in place, no EU data regions are configured, and there is no retention period: case records stay in Airtable, Notion and Slack until someone deletes them.

## 5. Does the system make or assist decisions that affect people?

It **recommends** tools, **flags** the described use as green, amber or red, and **scores** report confidence and use-case effort and impact. These outputs are about processes and tools, not about the employee. No human reviews the report before the employee acts on it. Green cases get no review, amber cases are posted to the Board's Slack channel for information, and red cases get a Board decision after the employee already has the report.

**Indirect risk:** the records link a department to its problems, its red flags and its feedback on tools. If this were used to judge teams or, in small departments, individuals, it would become evaluation of employees. Monthly summaries by department are planned but not built.
