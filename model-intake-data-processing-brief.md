# Model Intake Brief: data processing brief

**Assessment date:** 17 November 2026. **Scope:** existing local educational prototype, source commit `e384f3a41b5c74119786f55865ebe4e7e6cfb73c` (confirmed against GitHub HEAD). Evidence references: [register](model-intake-evidence-and-sources.md).

**System and actual use.** Model Intake Brief checks public model documentation against 18 evidence criteria and produces a Markdown report for a human governance reviewer. The owner confirms local, individual educational use, public model documents only, no real client data and no other users. No privacy notice, retention rules, deliberately selected processing regions or DPA documentation has been arranged. Standard vendor terms may incorporate a DPA; acceptance is unverified. [E1, E8]

**Personal data.** Organisation names, model specifications and legal passages ordinarily concern organisations or technology, not natural persons. However, public pages can contain author names, identifiable repository handles, named business contacts and email addresses; source URLs and quotes can preserve them. API traffic exposes the operator's IP address and account-linked request metadata to services. A synthetic probe proves that contact details survive into the outgoing LLM payload. Public-only input therefore does not establish absence of personal data. [E2, E3, E9]

**Sources and purposes.** The operator supplies a model ID and, for hosted models, a provider name. P1: find and retrieve public documentation and provenance. P2: assess documentation coverage and generate evidence-backed findings. P3: retain or share the report for human review and educational demonstration. P4: operate and troubleshoot requests through transient run state and vendor service metadata. A separate flow embeds non-personal regulatory text and checklist queries. No fine-tuning, customer-database ingestion or person scoring is implemented. [E1–E7]

**Flow and processors.** In live mode, the local Python/LangGraph process sends model queries to Tavily, URLs to Jina Reader, and model IDs to Hugging Face. Extracted snippets and up to 3,500 characters per source go to OpenAI's assessment API; link verification contacts source websites directly. OpenAI embeddings and Pinecone handle the regulatory branch. Results return to local memory, CLI output or the Streamlit session, then optionally to a downloaded file. Offline mode uses local fixtures and skips these API calls. [E2–E7]

**Location and retention.** Application processing is on the owner's computer; its physical jurisdiction is unconfirmed. External processing, support access, backups and contractual entities remain unverified, so EEA-only processing cannot be claimed. There is no application retention schedule or automatic deletion of exported reports; session state is not proof of secure erasure. `store: false` does not establish account-level zero retention. Non-EEA personal-data transfers require verified safeguards. [E3, E6, E8; L1, L4]

**Decisions and responsibility.** The tool flags documentation gaps about models and supports human procurement/governance research; it neither approves deployments nor decides a person's employment, credit or benefits. Human review is intended but not enforced by an approval workflow. The owner determines the prototype's purpose; future client/vendor roles depend on activities and contracts. [E1, E6; L1]
